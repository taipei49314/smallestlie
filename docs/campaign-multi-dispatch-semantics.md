`read_multi_dispatch_observations` acquires the exact cross-terminal source map,
original A/F/M, coordinator journal and each independently configured R_i before
forming runner/verifier semantics. `adjudicate_multi_dispatch_campaign` obtains
its own fresh snapshot and accepts only raw post-run reviews or explicit missing
reviews. These are separate versioned consumers; the v1 readers and public gates

## Own original facts and complete denominator

Every slot separates three views:

| View | Meaning |
| --- | --- |
| `recorded` | F's original reservation, disposition and matching coordinator release/ACK claims. |
| `configured` | Independently imported exact source/admission/publication configuration, including opaque acceptance refs. |
| `observed` | Reacquired R_i proof, raw digests, own dispatch, native measured facts, termination/writer disposition and output role refs; null if unavailable or rejected. |

A recorded completed disposition can coexist with a missing observed source.
It creates no eligibility or semantic result. Every frozen slot and case stays
in the snapshot, including rejected, missing and ineligible sources. F's common
dispatch and known repository/source roles remain explicit even when all R_i
sources are missing.

Acquisition reconstructs a private exact source configuration before GETs,
including nested stores, publication/admission/action grants and tickets. It
uses class readers on fresh stores and compares the caller configuration again
before returning. A persistent configuration change during acquisition rejects
the snapshot; it cannot mix opaque imported acceptances into previously acquired
proofs. The explicitly configured external transport remains the integration
trust boundary, and these constructors establish no real admission.

Each runner report is looked up by role/ref within its own R_i namespace.
Different actions can use the same path with different raw bytes. The complete
measured file set must match the frozen arm before a temporary pure-parser view
receives frozen tree/production labels. This view is not saved or presented as
a new native receipt. Completed semantics also require that command's completed
materialization, integer exit, complete outputs and reaped writers. Native
timeout, quota, signal, spawn failure and incomplete output facts remain visible
and cannot become green through F's job status or an old first-pass assessment.

F aggregate runner receipts, flat runner artifacts and case first-pass
validations are auxiliary raw views, not execution authority. Missing case
captures/first-pass refs are allowed. Malformed aggregate receipts are preserved
without lending a header or flat output map. A present fixed role that contradicts
an available original own-role output rejects the whole snapshot. Mandatory
ledger disposition validation refs and the seal's observation index remain
present and closed; missing auxiliary evidence does not relax those gates.

Verifier semantics use its own command and completed baseline/attack
materializations. Raw metadata binds actual measured command/range, frozen
trees, engine, native termination and output hashes. Policy support remains the
previously admitted default without policy directories or allowlisting, fail-on
high. Findings schema/counts, range labels, diagnostics, verdict and integer exit
must agree. Parsed source spans, unknown attachments and skipped files remain
visible when a later policy/channel check denies acceptance.

## Separate exact independent review

`smallestlie.multi-dispatch-case-review/v1` binds case/engine/residual index plus
the full snapshot, request/lock/plan/session, raw ledger/index/coordinator journal,
A/F/M, common dispatch, all slots' recorded/configured/observed summaries, imported
acceptance refs, source roles and complete own/twin semantic summaries. An
unrelated missing slot or recorded claim changes this context too.

`GitHubMultiDispatchReviewAuthority` requires separate exact
`MultiDispatchPostRunReviewGrant` entries and an exact independent human merge
registry. A grant binds raw review, request/lock/case, snapshot/context digests
and the separately imported semantic approval reference. Verification rebuilds
the exact nested governance roots/registry and freshly reads the actual merged
PR, changed blob and immutable Git bytes through class implementations.

This new contract requires the review repository to be distinct from product,
request and EC/source roles by case-insensitive full name and numeric ID. Review
merge commits cannot alias any known product/Phase1/EC source, A/F/M, configured
receipt/admission, recorded disposition receipt or coordinator release/ACK receipt
claim, including unavailable R_i. Known product/request human merge inputs are
also excluded. Source acceptance references cannot serve as review reference,
human approval or semantic approval. Old authorities/grants/schemas, an allowed
account and an ordinary framework merge do not supply this authority.

The shared pure content checks still require complete pinned source documents,
case-specific residual coverage/citations, frozen diff/theater paths and declared
near-shape contrast/fingerprints. Absence from a partial index proves no novelty.

## Rows and headline qualification

`smallestlie.multi-dispatch-adjudication/v1` retains the full snapshot and one
row per frozen case. Proven own DEF refutations become `killed_candidate` before
missing repair/twin/review can erase them. Valid blocks, unknowns, boundaries and
documented residuals remain separate verdicts. Controls retain their own outcome.

`confirmed_defect_case_count` counts reviewed candidate defects;
`paired_defect_case_count` is the qualified headline. A headline additionally
requires the parent twin and control's own effective cheating, matching declared
variants/command context, the control's own completed verifier/materializations,
and a nonallowlisted finding matching the declared rule/path, reviewed fingerprint
and effective threshold. An honest or repaired test is a separate control.
