# Frozen external source responsibilities

runner_materialize, runner_command, verifier_materialize and verifier_command
all bind one actual collector path/raw hash. Separate dispatches do not permit
different collector pins. The library cannot discover approvals/credentials,
publish, continue, retry, grant host admission or authorize a run.

EcReceiptStore.read authenticates collector bytes from root.repository at
grant.ec_source_commit. The later admitted EC source must preserve and execute
this identical collector at the same repository-relative path, together with
the frozen source/helper closure. A product-only copy is insufficient.
Do not put a product commit in ec_source_commit or substitute an unrelated EC
collector pin. Alternate source-origin wiring needs a versioned reviewed
contract. This document does not mutate/admit an EC workload or source.

Independent integration responsibilities:

- Human approval/merge registry: actual actor, Phase-1 commit/manifest and
  later request. Ordinary agent framework delegation is not that approval.
  Historical prior exploration is recorded.
- Host/capture/storage authority: private interpreter, restored images, launcher,
  explicit MinGit archive/executable/transitive loaders/system tools, actual
  host generation, process/network isolation and protected roots.
- Journal authority: exclusive/fsync/readback claims and crash rules, actual
  Windows durability primitive or explicit accepted limitation. Local fsync
  does not authenticate power-loss durability.
- Immutable publisher: entire original action inventory, diagnostics and every
  Git child sidecar, native cleanup and exact dispatch/publication identities.
- Coordinator: independently reacquire original accepted immutable ACKs before
  later release. Fresh receipt/authority instances read original materialization
  diagnostics to bind actual workspace paths; this sidecar needs explicit
  source/publication acceptance.
- Source/semantic reviewers: entire ordered action map and denominator,
  theater/scope/residual reconciliation and effective blocked twins.
  Source acceptance does not supply a case verdict.

Verifier setup begins after durable ticket ACK, creates real baseline/attack
commits in a third fresh workspace and checks native ls-tree/cat-file bytes
against both original ACKed maps. Every internal Git child has raw bounded
capture metadata/streams. Once actual range is known, canonical work_started
binds the final engine command. The five canonical events cover that command,
not earlier Git setup. Host/journal/coordinator must accept the true ordering;
no event is invented or backdated.

Failed setup consumes the ticket, keeps diagnostics/claims/prefix and leaves
completion absent. Actual nonzero exits remain observed; incomplete capture,
quota, spawn/timeout/truncation/writer/source failures remain unknown.
No retry or substitute successful capture. Git disables hooks/config inheritance.
Engine uses actual private Python and pinned zipapp, check HEAD~1..HEAD,
--format json, default fail_on high and frozen semantic environment.
The receiver requires -I -B flags; the engine's unchanged argv disables user
site through literal PYTHONNOUSERSITE=1. Full prefix identity alone does not
authenticate ambient loaders or user-site startup code.

Canonical verifier metadata retains the strict observation schema. Raw streams
remain unchanged; real adapter TargetVerdict diagnostics are separate.
A diagnostic/constructor is not a trusted envelope. After writers end, recheck
engine, real range, inputs, runtime and full source before completion qualification.

NOT_RUN: no source/host/storage/journal/publisher/coordinator/collector adoption,
exact human approval, formal execution grant/lock, W3 observation or verdict.
