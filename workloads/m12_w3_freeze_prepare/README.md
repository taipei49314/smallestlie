# W3 freeze preparation — proposed, not admitted

The strict Phase-1 profile binds actual executable, runner-package and complete
installed-file identities. Existing versions, wheel locks and successful install
logs do not provide those identities. This one bounded preparation supplies the
missing source inputs without running any W3 case or verifier.

The declaration is m12-w3-freeze-prepare, Windows x64 LAPTOP-50KP71KA only,
profile-ec-integrity, no cache or parameters, one dispatch, 35-minute outer
limit. Existing framework grants and admissions do not cover this entry.

## Exact private preparation

- Download CPython3.12.10's existing EC-pinned PSF NuGet package and extract its
  complete tools directory into a fresh job-private Python prefix. Download the
  eight compatible wheel URLs from this exact product uv.lock, verify every
  original raw hash, and unpack their complete regular-file wheel contents
  into Lib/site-packages. Unsupported wheel data schemes are refused. No venv,
  pip, installer scripts, generated entrypoint launchers or bytecode are used.
- Download the official Node24.19.0 Windows x64 ZIP, verify its published raw
  SHA-256 and node.exe digest, and extract into a separate private root.
- Use only that archive's node.exe and bundled npm CLI. The only initial JS
  dependencies are exact Mocha12.0.3, Chai5.3.3 and Vitest3.2.7. Resolve their
  complete lock before Phase1, require registry tarball integrity on every
  package, then npm ci using that lock. Both commands disable lifecycle scripts,
  audit and funding; npm config and cache are private. No Jest is selected.
- Run Node --version and one isolated CPython stdlib metadata program to bind
  the actual runtime and pytest distribution. The probe imports no product,
  pytest, Mocha or Vitest code. There is no case/reporting probe or test call.
- Measure complete regular-file trees for Python, Node and JS installations,
  plus the complete pytest/_pytest and Mocha/Vitest package trees. Archive every
  installation file, restore it into a fresh private directory and compare the
  complete raw map against both the original snapshot and a second source
  read. Preserve sealed ZIP bytes in ordered 8-MiB parts and their raw hashes.
  Publisher inputs have no junctions, links or token values.

Python runtime identity is the actual python.exe bytes. Pytest runner identity
is the canonical digest of the two complete pytest/_pytest package maps.
Python installed identity is the canonical digest of the complete actual
sys.prefix tree; the metadata probe must confirm this fresh portable prefix.
These definitions match the native producer's measurement definitions. Every
wheel and the entire runtime remain separate original integrity inputs.

Node runtime identity is actual node.exe bytes. Each JS runner identity is the
canonical digest of its full installed package map. JS installed identity is
the complete JS installation tree, including package.json, package-lock.json,
all node_modules and hidden files. The future external collector must use these
exact definitions and independently admit loader/module-resolution placement.
This preparation does not implement or accept that collector.

Canonical maps use sorted keys, ASCII JSON and comma/colon separators. Nothing
is excluded from the installation map; bytecode, caches and hidden files count
if present. Byte-identical archive restore does not establish that an arbitrary
later reinstall has the same identity. Phase2 must restore the sealed inputs
and remeasure them through its independently accepted collector.

## Fixed bounds and preserved output

Downloads are HTTPS-only from api.nuget.org/globalcdn.nuget.org, nodejs.org and
files.pythonhosted.org, with raw hash checks, 64-MiB per download and a bounded
stream read. npm registry traffic is limited by its explicit registry/config,
zero retries and 240/360-second command limits. This is application configuration,
not an OS network sandbox. The existing EC outer Job Object remains the hard
wall-time/process cleanup boundary.

Regular-file closures reject links/reparse paths, case aliases and unsafe
members. Node/JS images are capped at 50,000 files / 256 MiB per file, with
Node total 256 MiB and JS total 512 MiB. Python uses the native producer's exact
20,000 files / 10,000,000 bytes per file / 100,000,000 total-byte bounds.
Source status/HEAD is checked with hooks disabled
before and after successful preparation. Any failure leaves incomplete evidence;
no missing input is replaced by an intended hash.

The receipt retains exact argv/cwd, raw stdout/stderr, downloaded input
identities, actual native metadata, full file maps, locks, ordered archive parts,
restore equality and explicit preparation-only status. The EC publisher archives
the output after the job and supplies immutable commit/tree/blob identities.
Independent readback must authenticate all original bytes before these inputs
can populate profiles; a COMPLETE declaration is not source acceptance.

No global installation, permanent host change, toolchain/profile update,
product/runner adoption, formal approval/request or case execution is included.
All work stays within the fresh EC job's work/out roots and is subject to its
ordinary cleanup. No management credential is provided to the entry.
