# Multi-dispatch J recording and evidence re-verification

`record_multi_dispatch_adjudication` saves the complete report from the fresh
[multi-dispatch semantic consumer](campaign-multi-dispatch-semantics.md) in a new,
exclusive local directory. `verify_multi_dispatch_recording` reacquires the
original source and review authority, recomputes every row, and compares the
whole journal and referenced artifacts byte for byte. These framework APIs do
not launch work or create a campaign approval.

The independent `smallestlie.multi-dispatch-recording/v1` JSONL schema records
one start, a review disposition and adjudicated row for each frozen case in
order, then one summary and EOF. The start binds the complete roster, request,
lock, plan, session, canonical snapshot digest and its separately addressed raw
artifact. The snapshot retains A/F/M/coordinator journal, each action's own
source and output namespace, raw role/acceptance references, recorded claims,
configured contracts and observed facts. Missing or rejected sources and raw
reviews remain explicit; auxiliary findings and future attachments remain in
the complete stored rows.

The summary stores all rows, raw snapshot and separate candidate/qualified
headline counts. A real DEF refutation keeps the engine's kill priority even
when review, repair or twin qualification is missing. The recorder neither
changes the immutable F archive nor converts missing evidence into approval.

Recording captures raw review bytes once, computes the entire report and
bounded artifact/journal references before creating the directory, then writes,
synchronizes and reads back the artifacts before the journal. An existing or
interrupted root is refused. Failure does not resume, overwrite evidence or
append a successful summary. Plain path and regular journal file checks reject
linked/reparse and nonregular input. Windows directory-entry power-loss
durability still requires an independently adopted host/storage contract;
file synchronization and unit fault injection do not establish that contract.

Verification requires the trusted caller's external exact raw J SHA-256. It
does not infer expected identity from the journal or a bundle manifest. It
strictly checks native complete bytes, schema, sequence, chain, full roster and
event order, reads the raw reviews, then invokes the fresh semantic engine.
Saved snapshots, accepted objects, validation artifacts and closed counts never
replace fresh source acquisition. Coherently rehashed rows, substituted counts,
revoked/unavailable sources or reviews, and raw reencoding still fail the
recomputed journal comparison. Every referenced snapshot/review/validation/
row/summary artifact must retain its exact raw size, digest and bytes.

The returned local digest addresses content. It does not establish immutable J
publication, collector/publisher admission or actual human/semantic approval.
The [external J publication reader](campaign-multi-dispatch-recording-source.md)
uses the same private raw verification core. Portable witness and public GET-only
report gates remain later integrations. Legacy v1 and public v2 run/replay/minimize
gates retain their existing contracts. Actual human Phase1, adopted runner/
verifier/coordinator/storage, formal W3 and full M12 D remain unfinished.

Validation is NOT_RUN under POLICY `work-machine-local` until a new exact-source
pool grant is executed. The previous PR38 grant covers only its own source.
The unchanged admitted semantic workload keeps its original focused selection
and limits; its complete suite will include these new recording contracts on
the next separately authorized source.
